# Privacy-first Model Gateway — bounded foundation, NOT full HF integration

[ADR-005](../adr/ADR-005-private-model-gateway.md) · [OpenAPI](../../openapi.yaml).

## Purpose / scope
Provider-neutral text generation transport to separately operated OpenAI-compatible llama.cpp/vLLM/TGI/Ollama/custom/Hugging Face endpoints. No weights, transformers, smolagents, model download, remote repository execution or GPU work in Core. ModelProvider/AgentProvider/EmbeddingProvider/VisionProvider/SpeechProvider/RerankerProvider are contracts; only **OpenAI-compatible text** has an adapter. Other modality and autonomous agent implementations are NOT IMPLEMENTED. No placeholder responses or inferred provider availability.

Modes LOCAL, SELF_HOSTED, PRIVATE_ENDPOINT, EXTERNAL_PROVIDER are policy categories, not provisioned infrastructure. Private mode does not prove PrivateLink/private routing/region ownership. Registry revision/license/hardware/evaluation/security fields are manual reviewer attestations; backend revision, license compatibility and performance are NOT automatically verified. No model discovery or automatic model selection/offloading. No current installed model/live inference validation.

## Inputs / outputs / dependencies
Core stdlib HTTP/TLS + existing FastAPI/Pydantic/SQLite. Provider accepts `POST /v1/chat/completions` with model, one user message containing serialized selected context, max_tokens, stream=false. Requires usable string in choices[0].message.content, no tool_calls/function_call. It returns untrusted text, never a Decision/Approval. Does not accept arbitrary paths, extra headers, tool definitions, uploaded files or model-produced URLs. Output is returned transiently, not persisted in Memory/Cache. Audit stores its hash.

Task must be existing READ with preconditions; purpose analysis/plan/code supported by reviewed metadata. At most eight explicitly selected Evidence/Memory IDs total from same project. Task-bound Memory from another task is blocked. No implicit RAG query or database/filesystem dump. Selected context defaults to CONFIDENTIAL, even when caller labels prompt PUBLIC. All text is untrusted, not an instruction granting permissions. Recognized secret patterns and SECRET/CREDENTIAL classification block all modes before request persistence; no unsafe redact-and-send fallback. Regex is NOT comprehensive DLP and cannot prove absence of disguised/encoded secrets; exact human context review remains required.

## Configuration / permissions
Empty config means NOT CONFIGURED. Default policy: privacy_lock=true, local_only=true, external_ai=false, allow_remote=false, every allowlist empty. Policy can only be appended by reviewer. Existing requests bind policy/config hash; new policy invalidates old consent. Operator cannot select URLs/tokens, modify policy, register reviewed metadata or run inference. Reviewer authorizes exact context hash; shared role token is not individual identity.

Trusted JSON schema (values below describe fields, not a usable/fake configured provider): `providers[]` entries require `id`, `mode`, `origin`, `token_env`, `region`. `id` is a bounded identifier; `mode` one of the four modes; origin an administrator-reviewed server origin with no path/query/fragment/userinfo; token_env starts ATZE_AI_TOKEN_. Never place credentials in this file or repository. No runtime examples/seed registry supplied. Startup rejects duplicate IDs, invalid origins, plaintext off-host URLs. LOCAL accepts literal 127.0.0.1/::1 only, still with bearer auth. Every off-host connection uses verified TLS with minimum TLS 1.2. No redirects, environment proxies, automatic retries/fallback or anonymous requests. Local loopback HTTP stays on host; this is not permission for third-party plaintext.

## API workflow / side effects / errors
1. Reviewer POST `/api/ai/models` reviews concrete provider/model/revision (40–64 hex)/license/capabilities/context_length/hardware/evaluation/security_review. Produces immutable manual metadata, NOT live validation.
2. Reviewer POST `/api/ai/policy` selects exact provider IDs, **registry model IDs**, project IDs, task purposes, data classes and regions; sets context/output bounds. LOCAL-only remains default. Nonlocal requires privacy_lock=false, local_only=false, allow_remote=true. EXTERNAL_PROVIDER additionally external_ai=true. All allowlists required for LOCAL too.
3. Operator POST `/api/ai/requests`: task_id, model_id, purpose, classification (default CONFIDENTIAL), prompt, optional evidence_ids/memory_ids. Resolves bounded context locally, scans it and persists exact context for review; no network. Response includes id/context/context_hash/effective_classification/state.
4. Reviewer reads GET `/api/ai/requests/{id}`, inspects exact content, then POST `/api/ai/requests/{id}/run` with context_hash, reason (8–500 chars), and allow_remote=true only when intentionally permitting host exit. No full-project automatic selection.
5. Response envelope always has attempt, output (null on failure), allowed_for_action=false. **HTTP 200 is not model success**: inspect attempt.state: BLOCKED, UNAVAILABLE, DRAFT_UNCHALLENGED. PENDING_OUTCOME after crash means UNKNOWN, not safe to retry. GET `/api/ai/attempts/{id}` retrieves metadata.
6. Relevant conclusions require a separate structured `/api/results` package with actual evidence and mandatory Challenge/Triage. No automatic semantic extraction, model-generated evidence verification or adoption. Existing fact/decision direct-write ban remains.

GET `/api/ai/status` and `/api/ai/models` show actual policy/config/manual registry; configured is never reported as validated. UI shows this actual status and has a reviewer-only **AI** local-only lock clearing allowlists. Other settings/workflows API-only, no fake model dropdown or inference demo. This lock is NOT a universal firewall/MCP/browser lock.

401/403 auth; 404 missing entity; 409 preparation/scanner/config block; 422 schemas; 503 storage. Transport errors are generic UNAVAILABLE/BLOCKED in the attempt envelope; response bodies/credentials/URLs never included in errors. No global rate limiter. max_context_chars 1..16000 (default8000), max_output_tokens1..512(default128), response <=65536 bytes /16000 chars. Declared model context_length is metadata, not actual tokenizer admission or resource measurement. Requests with too much selected text block instead of truncating silently.

## Audit / consistency / failures / recovery
IDs, task/model/provider, context hash, classification, exact policy, permission actor/remote consent/reason hash, time, state, output hash, empty tools. Prepared input is local database content, not logs; encryption at rest is NOT implemented. Responses are not automatically cached. Denied preparation logs only reason code. Credentials never in request/audit records.

Before I/O, attempt PENDING_OUTCOME and request reservation commit. Policy/config/Stop checked again under database write lock before send; policy changes serialize with call. Socket timeout15s per blocking operation, NOT a hard wall-clock job deadline. Slow malicious servers/headers and in-flight cancellation require worker/ingress hardening; this is NOT a 2-GB latency/DoS guarantee. External dispatch and SQLite cannot commit atomically: crash after sending can leave unknown outcome; no automatic retry/fallback. Already-consumed requests cannot be replayed; manually creating a new request can cause another provider bill. No cost engine or cost guarantee.

Policy changes/Stop cannot recall already-transmitted data. Endpoint logs, provider retention/region and model identity are separate trust/contract gates. TLS does not prevent the destination from processing plaintext. The Python gateway controls only implemented model egress, not host admins, future plugins, existing independent Challenge control traffic or all platform networking. Universal OS egress enforcement is NOT IMPLEMENTED; release remains BLOCKED.

## Validation / tests
AI-001..009 in `tests/test_ai_privacy.py`: real SQLite/API and actual loopback HTTP/TLS sockets, including certificate rejection then explicitly trusted TLS receipt, no redirects/fallback, privacy/allowlists, role/context/secret/stop/stale/replay boundaries. The receiver computes a transport receipt from synthetic test bytes. It is **NOT a model**, never imported into app runtime, and cannot validate HF inference, model quality or sandbox isolation. No MCP/sandbox implementation exists to test; those acceptance gates are NOT RUN/BLOCKED, not simulated passes. Full executed outcomes in current validation report.

## Known limitations / next required gates
Actual pinned local HF model + runtime, model catalogue/revision/license/hardware verification, smolagents/AgentRuntime/tool registry, MCP transport/permission checks, independent-model challenge, resource/cost selection/offloading, genuine PrivateLink/external service validation, comprehensive classification/encrypted cache, OS/ingress egress isolation, hard deadlines, multi-user identity and browser E2E remain unimplemented/unvalidated. Full requested HF integration is not ready for release.
